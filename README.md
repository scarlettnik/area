# Прокладка тепловой сети

Расчёт сети по GeoJSON с выбором точек врезки, общими магистралями и обходом
препятствий. Python 3.14, внешние библиотеки не требуются.

## Запуск

```bash
.venv/bin/python heat_route_builder.py
```

По умолчанию читается `!!!_Датасет.geojson`, результаты сохраняются в
`routing_results/`. Трассы ориентированы по направлениям зданий, как на
`nedded.jpg`. Сетка — 5 м; для более подробного поиска можно передать
`--grid-step 2.5`. Мелкая сетка требует больше времени и памяти.
Оси определяются по преобладающей группе направлений длинных фасадов:
здания с другой ориентацией не уводят сетку от направления квартала.

```bash
.venv/bin/python heat_route_builder.py --input '!!!_Датасет.geojson' --output-dir routing_results
.venv/bin/python -m unittest -v
.venv/bin/python validate_routing.py
```

## Результаты

- `preview.svg` — схема с исходными зданиями, существующей сетью, новыми трубами и номерами потребителей; открывается в браузере.
- `best_variant.geojson` — лучший найденный вариант со сводной записью.
- `variants_ranked.geojson` — найденные варианты, ранжированные по стоимости.
- `openable_layers/best_lines.geojson` и `best_points.geojson` — раздельные слои для ГИС.
- `summary.json` и `report.md` — стоимость, длина, подключения и ограничения модели.

Врезки обозначены голубым, новая сеть — жёлтым, существующая — розовым.

## Что оптимизируется

Основная цель — официальный `score` из технического приложения: 70% стоимости
и 30% длины. В пределах 1% разницы по score варианты сравниваются по числу
micro-bends, поворотов и прямых углов. `calculated_cost` сохраняется отдельно
и входит в score вместе с длиной.

Точки врезки выбираются по стоимости доступного маршрута с учётом препятствий.
Для очередного потребителя сравниваются новая врезка и присоединение к
построенной сети. Каждое предложение пересчитывается целиком, включая рост
расхода и диаметра общих труб. Затем алгоритм пробует переподключить отдельные
ветви и целые группы потребителей. Проверяются два порядка построения сети;
`--max-topologies 1` ограничивает поиск первым порядком.
В конце постобработка геометрии (`refine_geometry`) устраняет мелкие уступы и пробует прямые
сокращения между существующими узлами. Каждое сокращение заново проверяет
здания, ограничения, clearance, пересечения, врезки и полный score. Геометрия,
стоимость и длины в выгрузке учитывают только принятые сокращения.

По умолчанию искусственной наценки за повороты нет: они используются как
геометрический tie-break для близких по score вариантов. `--bend-cost-rub` добавляет
явную стоимость поворота, а `--turn-penalty-m` задаёт предпочтение прямых
маршрутов во время поиска. `--no-orthogonal-corridors` разрешает диагональные
маршруты и безопасное геометрическое сокращение линий.

## Корректность и границы модели

Каждое ребро проверяется по геометрии препятствий, в том числе между узлами
сетки. Проверяются связность, отсутствие циклов, суммирование расходов,
диаметры и непрерывная длина одного диаметра через камеры. Экспорт сохраняет
реальные координаты подключений и согласованные идентификаторы узлов.

В этом датасете все точки подключения находятся внутри зданий. Только короткий
конечный ввод может выйти из собственного здания; проход через другие здания
запрещён. Это явное допущение для входных данных, а не разрешение вести
магистрали через здания. Недоступные подключения перечисляются в отчёте.

Это дискретная эвристическая оптимизация с локальным улучшением, без
доказательства глобального минимума. Результат зависит от шага сетки и набора
кандидатов. Специальные проходы и глубины проверяются, но реконструкция до
источника рассчитывается только при наличии расходов `flow_tph` и связей
`upstream_object_id` существующей сети.
Отступ от здания задан как 5 м до оси; от воды — 1 м, от железной дороги — 2 м.
В исходном файле отсутствуют расходы существующей сети и `upstream_object_id`,
поэтому нулевая стоимость реконструкции означает отсутствие расчёта, а не
подтверждённое отсутствие потребности в реконструкции.

`validate_routing.py` отдельно читает выгруженный GeoJSON и проверяет геометрию,
ссылки на узлы, пути до врезок, баланс расходов, непрерывные длины и суммы
стоимости. Проверки относятся к описанной модели, не ко всем требованиям
инженерного проекта.
